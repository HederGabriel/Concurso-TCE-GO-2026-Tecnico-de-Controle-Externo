# Links físicos e simbólicos no Linux — Revisão Rápida

## 1. Links físicos (*hard links*)

- Apontam para o mesmo **inode** do arquivo original.
- Compartilham o mesmo conteúdo; não são cópias independentes.
- Se o nome original for excluído, o conteúdo continua acessível enquanto existir outro link físico válido.
- Tradicionalmente, não podem ser criados para diretórios nem atravessar sistemas de arquivos diferentes.

## 2. Links simbólicos (*soft links*)

- Funcionam como atalhos que armazenam o caminho do destino.
- Podem apontar para arquivos ou diretórios.
- Podem atravessar sistemas de arquivos diferentes.
- Se o destino for excluído ou ficar inacessível, o link pode se tornar quebrado (*dangling link*).

## 3. Comparação

| Característica | Link físico | Link simbólico |
|---|---|---|
| Compartilha o inode do destino | Sim | Não |
| Pode atravessar sistemas de arquivos | Não | Sim |
| Pode apontar para diretórios (regra geral) | Não | Sim |
| Sobrevive à exclusão do nome original | Sim | Não, se o destino desaparecer |

## 4. Resolução da questão

1. **Verdadeira:** na regra tradicional do Linux, links físicos não podem ser criados para diretórios; arquivos especiais também possuem restrições, dependendo do tipo e das ferramentas utilizadas.
2. **Falsa:** links simbólicos podem apontar para destinos em outros sistemas de arquivos.
3. **Verdadeira:** o conteúdo permanece disponível enquanto existir pelo menos um link físico válido para o inode.

**Gabarito: D — V, F, V.**

**Macete:** link físico = mesmo inode; link simbólico = caminho do destino.
